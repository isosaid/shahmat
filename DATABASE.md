# Подключение базы данных

Сайт работает в двух режимах.

| | Локальный (по умолчанию) | Облачный |
|---|---|---|
| Где данные | только в браузере | PostgreSQL на сервере |
| Пароли | контрольная сумма, не защита | хеширование на сервере |
| Проверка прав | в браузере, обходится | на сервере, обойти нельзя |
| Видно с другого устройства | нет | да |
| Годится для реальных клиентов | **нет** | да |

Локальный режим — для показа и разработки. Ниже — как включить настоящую базу.

---

## Шаг 1. Создайте проект

1. Зайдите на **supabase.com** и создайте бесплатный аккаунт.
2. **New project** → задайте название и пароль базы → **Create**.
3. Подождите 1–2 минуты, пока проект развернётся.

Бесплатного тарифа хватает примерно на 50 000 активных пользователей в месяц.

## Шаг 2. Создайте таблицы

1. В проекте откройте **SQL Editor** → **New query**.
2. Откройте файл `schema.sql` из этой папки, скопируйте его целиком и вставьте в редактор.
3. Нажмите **Run**.

Будут созданы таблицы профилей, прогресса, тестов, задач, сертификатов, истории активности, новостей и курсов, а также политики доступа и представление для дашборда.

## Шаг 3. Подключите сайт

1. В Supabase откройте **Settings → API**.
2. Скопируйте **Project URL** и ключ **anon public**.
3. Откройте сайт, войдите администратором, перейдите **Админ → База данных**.
4. Вставьте оба значения и нажмите **Подключить**.

Появится сообщение об успешной связи. С этого момента регистрация и вход идут через сервер.

### Про ключ anon

Этот ключ специально предназначен для публикации в коде сайта — его видно всем, и это нормально. Доступ к данным ограничивают политики RLS на сервере: даже зная ключ, посторонний увидит только свои записи. **Ключ `service_role` в сайт вставлять нельзя никогда** — он обходит все политики.

## Шаг 4. Назначьте себя администратором

1. Зарегистрируйтесь на сайте обычным способом.
2. В Supabase откройте **SQL Editor** и выполните, подставив свою почту:

```sql
update public.profiles set role = 'admin' where email = 'ваша@почта';
```

3. Перезайдите на сайте — появится вкладка «Админ».

---

## Что видит администратор

**Дашборд** — сколько всего пользователей, сколько зарегистрировалось сегодня и за неделю, сколько активны, заблокированы, сколько выдано сертификатов, средний результат тестов. График регистраций за 14 дней. Таблица «Кто регистрировался»: имя, почта, дата регистрации, последняя активность, прогресс, роль. Выгрузка в CSV.

**Пользователи** — поиск, смена роли, блокировка, удаление.

**Аналитика** — распределение по уровням подготовки.

**Курсы** — список с автором, длительностью и статусом.

## Структура базы

| Таблица | Назначение |
|---|---|
| `auth.users` | почта и хеш пароля (создаётся Supabase) |
| `profiles` | имя, контакты, роль, блокировка, шахматные данные, баллы |
| `lesson_progress` | пройденные уроки |
| `quiz_results` | результаты тестов, попытки |
| `puzzle_results` | решённые задачи |
| `certificates` | выданные сертификаты с номером |
| `activity_log` | история действий |
| `news`, `courses` | контент, управляемый администратором |
| `chat_rooms` | комнаты чата (общий, вопросы по обучению) |
| `chat_messages` | сообщения чата |
| `admin_dashboard` | представление со сводкой по каждому пользователю |

## Чат

Чат между разными людьми работает **только с подключённой базой** — без неё сообщения остаются в одном браузере и не доходят до собеседника. Таблицы `chat_rooms` и `chat_messages` создаются тем же файлом `schema.sql`, отдельных действий не требуется.

Сообщения приходят автоматически: если в Supabase включён Realtime — мгновенно, иначе страница опрашивает базу раз в 5 секунд.

Права в чате: читают все вошедшие, пишут от своего имени, удаляют своё сообщение автор или администратор. Заблокированный пользователь писать не может — это проверяет сервер, обойти нельзя.

## Если что-то не работает

**«Не удалось подключиться»** — проверьте, что адрес начинается с `https://` и без косой черты в конце, а ключ скопирован целиком.

**Регистрация проходит, но в дашборде пусто** — не выполнен `schema.sql`, из-за чего нет триггера создания профиля. Выполните файл заново.

**Вкладка «Админ» не появляется** — не выполнен шаг 4, либо нужно выйти и войти снова.

**Письма подтверждения не приходят** — в **Authentication → Providers → Email** отключите **Confirm email**, либо настройте свой SMTP.
